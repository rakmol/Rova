# Pilot implementation contracts

Migration: `apps/api/db/init/014_accra_pilot.sql`. Apply using `npm run db:migrate`. Run `npm run admin:maintenance --workspace @rova/api` daily in a proven scheduler; it prunes diagnostic batches and expired lease hashes alongside existing admin maintenance. Expired incident retention may cascade associated precision evidence; rates therefore describe retained assessed reports, not an immutable lifetime baseline. No production scheduler is provisioned here.

## Public diagnostic API (no driver sign-in)

- `GET /v1/pilot/status`: collector flag, consent version, retention and corridor restriction. No participant/location input.
- `POST /v1/pilot/telemetry/session`: strict `{consent:true, consentVersion:1}`; only when server collector enabled. Returns random 256-bit token and seven-day expiry. Server stores only its SHA256 hash, with a creation **day**, not account/device identity. Session creation has a five-per-IP/day in-process limiter; ingestion also has a durable 48-unique-batches/lease/day cap. These controls deter simple abuse, not coordinated fraudulent metrics or a count of real people. Multi-replica ingress abuse protection still needs operations review.
- `POST /v1/pilot/telemetry/batches`: Bearer lease, strict `{batchId,day,version,build,variant,counts}`. `batchId` UUID, day ISO date in current/recent seven-day window, build numeric or `unknown`, variant one of development/preview/production/unknown. Counts accept only shared enum keys, integer 0..10000, sum at most10000; body at most8192 bytes. Unknown keys/route/coordinate/error/account fields are rejected. Current GPS/routes are not accepted. One receipt is idempotent under a row lock across replicas. Raw token and precise event time are not persisted. Server default daily creation/receipt metadata remains.
- `POST /v1/pilot/telemetry/erase`: Bearer lease, `{}`. Locks/revokes the same session before deleting contributions, so a concurrent or subsequent ingest cannot resurrect them. Idempotent, remains available when the collector flag is false. Deletion retries use the encrypted credential after opt-out; public/account data and provider requests have separate retention/deletion policies.

Mobile endpoint: `EXPO_PUBLIC_PILOT_API_URL=https://<permanent-api>/v1/pilot` (no credential). Dev Expo tunnel proxies only these allowlisted paths, not admin endpoints. Plain HTTP is accepted only for localhost testing. Server flag `PILOT_TELEMETRY_ENABLED=false` defaults off. Mobile consent is separately persisted encrypted and defaults off. No sign-in needed, no diagnostic SDK/upload on behalf of a non-consenting guest. Normal route/search processing still runs for navigation.

The encrypted queue stores at most14 day/build buckets plus one persisted UUID receipt. Retry keeps that exact receipt until acknowledged, then advances; background/foreground timer attempts at most every30 minutes, requests time out after12 seconds, no foreground blocking. Expired queues are trimmed on active flush; process death can delay persistence/cleanup, and counters may be lost. Upload failures never block navigation. Seven-day lease renewal is pseudonymous and previous lease contributions are erased when the active queue next retries. A reinstall can lose the token needed for immediate erasure. Do not claim complete or fraud-proof crash analytics.

Native local module `RovaDiagnostics` asks Android's own-process exit history for aggregate Java/native crash and ANR counts on Android API30+. It never reads trace streams or transmits process IDs, exit records, precise timestamps or paths. Only invoked after consent; pre-consent records are excluded by local watermark. Build changes/history truncation record a history gap; the dashboard withholds the crash ratio for that group. Unsupported OS/old APK means unavailable. The native module must be compiled and verified on devices; autolinking alone is insufficient.

## Operations API (existing admin auth/roles, same-origin BFF)

- `GET /v1/ops/pilot`: viewer and above. Small-group-suppressed build metrics, counter denominators, corridor state, rule freshness, independent incident assessment and provider reservation usage; actual invoiced spend is null. Current readiness is explicitly NO_GO pending manual evidence.
- `POST /v1/ops/pilot/corridors`: editor/administrator. `{id?,expected?,name,segmentIds,evidence,stage,validFrom,expiresAt,comment}`.1..64 unique real published UUIDs; maximum30-day window; edits increment revision/reset draft/independent approvals. Commentary and audit before/after retained.
- `POST /v1/ops/pilot/review`: reviewer/administrator. `{id,revision,decision:"approve"|"reject",comment}`. Current revision, non-author, one append-only decision per reviewer/revision. Rejection requires a new revision to resolve.
- `POST /v1/ops/pilot/control`: administrator. `{id,revision,action:"activate"|"pause",comment}`. Activation requires at least two distinct non-author current-revision approvals within seven days, no rejection, current evidence/members/validity. Pause is audited; expiry/freshness/withdrawal fail closed without a scheduled job.
- `POST /v1/ops/pilot/incident-check`: reviewer/administrator. `{reportId,revision,judgment:"confirmed"|"false"|"uncertain",evidence}`. Current unexpired report; immutable judgment per reviewer/revision, independent evidence protocol still human responsibility. Two agreeing reviewers required for assessed metrics. Conflicting reviews are excluded, not a majority vote or automatic confirmation.

Corridor member eligibility requires a published non-synthetic road/rule with current source, high confidence (>=.9), road accuracy<=10m, known road kind, rule review within180 days, official/field-audit source published within365 days, km/h and the underlying independent rule/publication approvals. The provisional planning bounding box[-0.5,5.4,0.35,6.1] contains the Accra pilot area; it is **not an official administrative boundary or an Accra-wide enablement**. Exact eligible scope is the individually reviewed road segment list. Numeric applicability still uses class/direction/GPS/parallel-road ambiguity checks; the gate runs **after** road matching, so it cannot ignore an unreviewed parallel road to pick an approved one.

`PILOT_REGION_GATING_ENABLED` defaults true in production and false in dev/test (set true explicitly for pilot services). Production should retain it; an active corridor still cannot invent a speed limit or enforcement location. Reported enforcement-road prompts are disabled in gated mode. Community incident reports remain separately marked community evidence; the operational beta must stay inside approved corridors. Stage metadata does not authenticate beta participants. Pilot offline pack API is disabled, and preview/production EAS profiles enforce `EXPO_PUBLIC_PILOT_MODE=true` so even a cached old safety pack cannot supply numeric limits. Basic mapping/routing remains available outside a corridor with unknown safety limits; full offline routing is not promised.
